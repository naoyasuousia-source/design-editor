# design-editor 重要仕様まとめ (important.md)

本ドキュメントは、要素の取扱い、AI連携、および編集機能に関する重要な仕様と、過去の主要な修正事項を新仕様環境（insert.md）の文脈に基づき集約したものである。今後の開発、およびAIによるコード生成時の最重要リファレンスとして活用すること。

## 1. 要素の基本仕様と挿入機能（新仕様）
エディタにおける要素の扱いは、親子階層を排除したフラットな構造を基本とする。

- **要素のフラット化の原理**:
    - エディタのキャンバス（DesignSurface）上には親子関係の概念は存在しない。全ての要素はルート直下のフラットな階層に配置される。
    - AIが生成時に複合要素（親子構造）を作成したとしても、エディタ反映時に全てIDを持つフラットな要素に変換される。
    - 元の親子関係にあった要素群は、エディタ上では「共通のグループIDを持つフラットな要素の集合」として再定義され、レンダリング時にグループとして振る舞う。
- **挿入（Insert）メニュー**:
    - グローバルメニューバーに「挿入」ボタンを配置。ここから「画像」または「テキストボックス」を選択して追加する。
    - 画像挿入時は、プロジェクトフォルダ内の `/images` ディレクトリから選択する形式をとる。
    - 挿入された要素はデフォルトでグループに属さない独立要素となり、キャンバスの中央付近に配置される。
- **レガシーUIの廃止**:
    - 従来の「ASSETS」パネルは完全に廃止された。素材の追加は全て「挿入」メニューおよびAI提案を起点とする。

## 2. グループ化とUI操作の革新
グループ化された要素は、一括操作の利便性と個別編集の柔軟性を両立するUIで制御される。

- **グループ選択の状態（第1段階）**:
    - グループに属するいずれかの要素をクリックすると、グループ全体がオレンジ色の枠線で囲まれる。
    - この枠線は通常の個別選択枠（水色）の2倍の太さを持ち、グループの一体感を強調する。
    - 四隅にオレンジ色のポイントが表示され、これらをドラッグすることでグループ内の全要素をレスポンシブに一括拡大縮小できる。
    - **スケーリングの制約**: レイアウト崩れを防ぐため、グループ全体に対して横方向のみ、あるいは縦方向のみの変形（一方向への引き伸ばし）は不可とする。
- **個別選択の状態（第2段階）**:
    - オレンジ枠が表示されている状態で、同じ要素を再度クリックすると、オレンジ枠を維持したまま、その要素に水色枠とポイント（個別選択UI）が表示される。
    - この状態で、グループの一員としての配置を保ちつつ、テキスト内容や個別スタイルを編集することが可能になる。
- **グループの動的管理**:
    - シフトキーを用いた複数要素選択により、動的に「グループ化」が可能。
    - グループ選択時には「解除ボタン」および「グループごと削除ボタン」が表示され、管理を容易にする。

## 3. AI生成・編集ルール（メタメッセージ）
AIがデザインを生成、または外部ファイルとして更新する際に遵守すべき重要ルール。

- **フォント利用の厳格化**:
    - 以下の15種類以外のフォント指定は禁止とする：
      Noto Sans JP, Noto Serif JP, 游ゴシック (Yu Gothic), 游明朝 (Yu Mincho), メイリオ (Meiryo), M PLUS 1p, Zen 角ゴシック New, Inter, Montserrat, Roboto, Playfair Display, Oswald, Poppins, JetBrains Mono, Times New Roman
- **要素の独立性と構造制約**:
    - テキストボックスはプレーンなテキスト、あるいはラインブレイクのみを含む。内部に他のID付き要素（画像や別のテキスト）を入れ子状に配置してはならない。
    - 全てのグラフィック要素、画像、装飾パーツは独立した要素（タグ）とし、それぞれに一意の `id` を付与する。
- **外部リソース（画像）の参照**:
    - 挿入または提案する画像は、必ず `./images/` フォルダ内のファイルを参照するパスを使用する。
- **HTMLの3領域構造**:
    - 保存されるHTMLは `<!-- DESIGN_START -->`, `<!-- CUSTOM_CSS_START -->`, `<!-- USER_REQUIREMENT_START -->` の3エリアに分かれる。
    - AIはデザイン更新時にこれらの領域を適切に書き換え、エディタはこれをパースして反映する。

## 4. 編集・スタイリングの詳細仕様
プロレベルのデザイン品質を担保するための技術的要件。

- **袋文字（Outside Stroke）の実現**:
    - 標準の `-webkit-text-stroke` は文字の内側を潰すため、`paint-order: stroke fill` を併用する。
    - これにより、ストロークの上に塗りを重ねる描画順序となり、文字の太さを損なわない外側縁取りが可能になる。
- **段落と視覚効果**:
    - `ParagraphSettings`: 文字揃え（左/中/右）、縦書き/横書き、文字間隔（letter-spacing）、行間隔（line-height）をサポート。
    - `EffectSettings`: `text-shadow`（影）、背景色・パディング・角丸（装飾）の実装。
- **レスポンシビリティの精密化**:
    - リサイズ中にレイアウトがわずかにズレる「誤差の累積」を防ぐため、操作開始時の初期値をDOM属性（`data-start-*`）に固定し、常に初期状態からの比率で座標とサイズを決定する。

## 5. 同期ロジックとファイル管理
外部編集とエディタを安全に接続するための仕様。

- **AIリンク（自動同期）**:
    - Viteの Websocket または Polling を通じて、外部でのファイル保存を検知。
    - 検知時は即座にキャンバスの `content` を仮反映し、ユーザーに「承認」または「破棄」を選択させるフローを通す。
- **自己保存ループの防止**:
    - エディタが保存を実行する際、その直前のタイムスタンプを `lastSaveTime` として記録。
    - ファイル変更検知時に、その変更が自分自身の保存によるものか、外部モデルによるものかをタイムスタンプの比較（数秒以内の誤差を許容）で判定する。
- **キャンバス比率の永続化**:
    - `PageSize` (A4, 9:16, SQUARE等) は、HTML内の `MetaMessage` (USER_REQUREIMENT) に保存される。
    - ファイルを開く際、このメタデータから比率を復元し、キャンバスサイズを自動調整する。

## 6. 技術的なハマりどころと解決策（過去の修正履歴より）
再発しやすい問題と、現在適用されているベストプラクティス。

- **HTMLパース時の注意**:
    - `DOMParser` を使って抽出した HTML フラグメントは、時として空になるケースがある。これを防ぐため、パース前にダミーのルートで包む工程を挟んでいる。
- **ベンダープリフィックスの変換**:
    - JSの `style.setProperty` を使う際、`webkitTextStroke` は自動で `webkit-text-stroke` になるが、CSSとしては `-webkit-text-stroke` である必要がある。`applyStyle` 関数内で先頭の `-` 不足を補正するロジックが組み込まれている。
- **メニューの見切れ防止**:
    - 要素が画面上部にある場合、フローティングメニューが画面外にはみ出す。要素の `rect.top` が小さい場合は、メニューを要素の下側に展開し、レイアウトを反転させる制御を行っている。
- **スライダー反映のパフォーマンス**:
    - 角丸や文字間隔などのスライダー操作時に、フレームごとにグローバルストアを更新すると、DOMの全置換が発生し、メニューの追従が遅れる「暴れ」が発生する。
    - 対策として、スライダー操作中はストア更新をスキップして直接 DOM の `style` を書き換え、操作終了時（MouseUp）に一度だけストアに同期する方式を採用している。
- **トリミングの座標計算**:
    - `html-to-image` でのトリミングは、キャンバスのズーム率（transform: scale）を考慮した絶対ピクセル計算が必要。ImageSaveWizard ではこの補正ロジックが実装されている。

## 7. 主要な改善・バグ修正履歴（重要ナレッジ）
過去の困難な課題とその解決アプローチの記録。

- **2026-01-03: 「開くと白紙になる」問題の解決**
    - 原因: `extractDesignContent` が HTML フラグメントの抽出に失敗し、空のコンテンツを返していた。
    - 対策: `DOMParser` 使用時にダミーのルート要素 (`<div>`) で包むことでパース精度を向上させ、確実に `.DesignSurface` を抽出・剥離できるように改善。
- **2026-01-03: 完全なレスポンシビスケーリングの実装**
    - 課題: リサイズを繰り返すと、浮動小数点誤差の累積により子要素のレイアウトが数ピクセルずつズレていく。
    - 解決: リサイズ開始時 (`onResizeStart`) に現在の全プロパティを一時属性として固定。リサイズ中は「現在のドラッグ量 / 開始時のサイズ」の比率を初期値に掛ける「絶対比率計算」に切り替え、誤差の連鎖を断ち切った。
- **2026-01-03: テキスト・図形の判定ヒューリスティックの強化**
    - 課題: `contenteditable` で改行（BR等）を許可した結果、複数のテキストボックスを内包するレイアウトコンテナが「テキスト要素」と誤認されるようになった。
    - 解決: 「子要素がIDを持っているか」を判定基準に追加。ブラウザが生成する改行用要素にはIDがないが、エディタ上の独立要素には必ずIDがあるため、これを利用してコンテナとテキストボックスを正確に分離した。
- **2026-01-03: EyeDropper（スポイト）の汎用化**
    - 課題: スポイト機能が特定のスタイル (color) に直結しており、影や袋文字の色取得に流用できなかった。
    - 解決: `openEyeDropper` を高階関数化し、取得した色をどう処理するかをコールバックで渡せるように変更。これにより、あらゆるプロパティへのスポイト適用が可能になった。
- **2026-01-03: ビルドエラーと型安全性の向上**
    - 課題: 開発中の副作用で未使用変数や型の不整合が発生し、デプロイが頻繁に失敗していた。
    - 対策: `Moveable` のイベント型 (`HTMLElement | SVGElement`) の厳密化、未使用のインポートや変数の徹底的なクリーンアップを実施。
- **2026-01-01: セーブロック機能の導入**
    - 課題: 自分でファイルを保存した際の変更通知を「外部編集」と誤認し、無限に同期ダイアログが出る。
    - 対策: `lastSaveTime` を `Ref` および `Store` で管理。OSのファイル変更検知のタイムスタンプと比較し、自前保存から 2000ms 以内の変更は無視するガードロジックを実装。
